[`e2e-real/STATUS.md`](e2e-real/STATUS.md).

نکته‌های صادقانه دربارهٔ این آزمون:

- بعضی ردیف‌های بک‌اند در لحظهٔ آزمون «مرده»اند: تونل را قبول می‌کنند ولی ترافیک عبور نمی‌دهد.
  اپ این را تشخیص می‌دهد (بخش ۴ همین سند) و درایور حداکثر ۵ ردیف را امتحان می‌کند. این
  رفتار عمدی است و در گزارش به‌صورت «ردیف n وصل نشد؛ ردیف بعدی» ثبت می‌شود.
- نتیجهٔ هر اجرا بسته به سلامت سرورها متفاوت است؛ «سبز بودن» یعنی **حداقل یک** مسیر کامل
  (دریافت → اتصال → ترافیک → تغییر → قطع) بدون خطای برنامه انجام شده است.

بازتولید:

## ۴) چرا «متصل» بدون ترافیک نمایش داده نمی‌شود

رفتار اپ اصلی این بود که به‌محض بالا آمدن هسته، «متصل» را نشان می‌داد — حتی اگر سرور مرده
باشد. در این نسخه، `VpnTunnelService.connect()` پس از بالا آمدن هسته این کار را می‌کند:

1. وضعیت را روی «در حال آزمایش عبور ترافیک…» می‌گذارد؛
2. یک `GET /cdn-cgi/trace` **از طریق پورت SOCKS خود هسته** (`127.0.0.1:10808`) می‌فرستد؛
3. اگر پاسخ `HTTP/…` بیاید ⇒ «متصل»؛
4. اگر تا ۳ تلاش پاسخی نیاید ⇒ پیام «ترافیک از تونل عبور نکرد؛ این سرور پاسخ نداد» و بستن تونل.

کد: `app/src/main/java/co/asiven/vixentvpn/service/VpnTunnelService.kt`
(`verifyThroughTunnel`, `requestThroughSocks`). در لاگ‌های CI این خط دیده می‌شود:

```
I MvpnTrial: آزمون ترافیک موفق: «HTTP/1.1 301 Moved Permanently» در 812ms
```
